# Q11. CORSとは

## 問題

フロントエンド（5173）からバックエンド（8080）にアクセスする際、

「CORS」という仕組みが関係します。

CORSとは何のためにありますか？

## 回答

「CORS」は Cross-Origin Resource Sharing の略で、別のオリジンへのアクセスを、アクセス先のサーバーが許可するための仕組みです。

ブラウザは、プロトコル・ホスト名・ポート番号の組み合わせを1つの出どころ(オリジン)として扱い、あるオリジンのページから別のオリジンへのアクセス結果を、勝手に読ませないというルールを持っています(同一オリジンポリシー)。悪意のあるサイトのプログラムが、利用者のブラウザを使って別のサイトのデータを読み取ることを防ぐためです。`localhost:5173` と `localhost:8080` は、ホスト名が同じでもポート番号が違うため、別のオリジンとして扱われます。

しかし、このアプリのように、フロントエンドがバックエンドの API を呼び出す構成では、別のオリジンへのアクセスが必要です。そこで、バックエンドが「フロントエンド(5173)からのアクセスは許可する」と宣言し、ブラウザがそれを確認して通します。この宣言の仕組みが CORS です。

アクセスを止めるのはサーバーではなくブラウザであり、サーバーは許可するオリジンを宣言する役割です。

CORS は、ブラウザが別のオリジンへのアクセスを制限する安全のルールに対して、必要なアクセスだけをサーバーの宣言で例外的に許可するためにあると理解しました。

## 理解のメモ

- CORS = Cross-Origin Resource Sharing。別のオリジンへのアクセスを、サーバーが許可するための仕組み。
- オリジン = プロトコル + ホスト名 + ポート番号。`localhost:5173` と `localhost:8080` は別のオリジン。
- ブラウザの同一オリジンポリシーは、悪意のあるサイトが利用者のブラウザを使って他のサイトのデータを読み取るのを防ぐためのルール。
- アクセスを止めるのはブラウザ。許可するオリジンを宣言するのはサーバー。
