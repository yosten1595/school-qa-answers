# Q15. データの流れ

## 問題

ユーザーが「新しいタスクを作成」ボタンを押してから、

- データベースに保存される
- 画面に反映される

までの流れを順を追って説明してください。

## 回答

「新しいタスクを作成」ボタンを押してから画面に反映されるまでは、次の流れになります。

1. ボタンを押す: ユーザーが、フロントエンドの画面でタスク名などを入力して、「新しいタスクを作成」ボタンを押します。
2. リクエストを作る: フロントエンドが、入力内容を JSON にまとめます。たとえば `{"title": "牛乳を買う"}` のような形です。
3. リクエストを送る: フロントエンドが、バックエンド(`localhost:8080`)の API に、POST メソッドでリクエストを送ります。フロントエンド(5173)とバックエンド(8080)は別のオリジンなので、バックエンドが CORS でこのアクセスを許可していることが前提です。
4. バックエンドが受け取る: バックエンドがリクエストを受け取り、入力内容をチェックします。たとえば、タスク名が空でないかを確かめます。問題があれば、400 のステータスコードで返します。
5. データベースに保存する: チェックが通れば、バックエンドがデータベースに新しいタスクを保存します。
6. レスポンスを返す: 保存できたら、バックエンドが、作成したタスクの内容を JSON にして、201 のステータスコードで返します。保存に失敗した場合は、500 などで返します。
7. 画面に反映する: フロントエンドがレスポンスを受け取り、返ってきたタスクを画面のリストに追加して表示します。

「データベースに保存される」のは 5 の段階で、「画面に反映される」のは 7 の段階です。保存が成功してレスポンスが返ってきてから、画面に反映されます。

ボタンを押してから、フロントエンドが POST でバックエンドに送り、バックエンドがチェックして保存し、結果を返したものをフロントエンドが画面に反映するという流れだと理解しました。

## 理解のメモ

- 流れは、ボタン → JSON にまとめる → POST で API に送る → バックエンドがチェック → データベースに保存 → 201 と JSON で返す → 画面に反映。
- 新規作成のリクエストは POST、成功のレスポンスは 201。入力に問題があれば 400、保存の失敗などサーバー側の問題は 500。
- フロントエンド(5173)からバックエンド(8080)への送信は、別のオリジンなので、CORS の許可が前提。
- 画面に反映されるのは、保存が成功してレスポンスが返ってきたあと。
- 画面の更新のしかた(返ってきたデータを追加する、一覧を取り直すなど)はアプリによって違う。
