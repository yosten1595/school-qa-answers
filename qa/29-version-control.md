# Q29. バージョン管理（Git）

## 問題

Gitなどのバージョン管理システムとは何ですか？

なぜ必要ですか？

使わないとどんな問題が起きますか？

## 回答

バージョン管理システムは、ファイルの変更の履歴を記録し、いつでも過去の状態に戻したり、変更を比べたりできる仕組みです。Git はその代表的なソフトです。変更を1つのまとまりとして記録することをコミット、本流から枝分かれした作業用の流れをブランチと呼びます。履歴をインターネット上のリモート(GitHub など)に置けば、チームで共有できます。ブランチの変更を本流に取り込んでよいかを確認してもらう依頼が、プルリクエスト(PR)です。

バージョン管理が必要なのは、次の理由からです。

- 過去に戻れる: 変更して不具合が出ても、前の状態に戻せます。
- 変更の履歴が分かる: 誰が、いつ、何のために変えたかが追えるため、不具合の原因を探しやすくなります。
- 複数人で同時に作業できる: それぞれのブランチで作業し、あとで統合できます。同じ箇所を直してぶつかったときは、どこがぶつかったかが分かります。
- 安全に試せる: ブランチで新しい機能を試し、うまくいったら本流に取り込めます。
- バックアップになる: リモートに履歴があれば、自分のパソコンが壊れても失われません。

使わないと、次のような問題が起きます。

- ファイルが増える: 「資料_最終」「資料_最終2」のように、バージョンごとにファイルをコピーして残すことになり、どれが最新か分からなくなります。
- 戻せない: 変更を上書きしたあとで元に戻したくなっても、戻せません。
- 上書きの事故: 2人が同じファイルを別々に直して保存すると、後から保存した方が、先の人の変更を消してしまいます。
- 履歴が追えない: いつ、誰が、なぜ変えたかが分からず、不具合の原因探しが難しくなります。
- 共有がしにくい: 最新の状態をメールなどで送り合うことになり、取り違えが起きます。

このリポジトリでも Git を使っています。各問を1つのコミットとして積み、`main` ではなくブランチで作業し、最後に PR にまとめて `main` に取り込んでもらう流れです。

バージョン管理は、変更の履歴を記録して、戻したり共有したりできる仕組みであり、使わないと、戻せない、上書きされる、履歴が追えないといった問題が起きると理解しました。

## 理解のメモ

- バージョン管理 = ファイルの変更の履歴を記録し、過去に戻したり、変更を比べたりできる仕組み。Git はその代表。
- 用語: コミット = 変更を記録するまとまり、ブランチ = 枝分かれした作業用の流れ、リモート = 履歴を共有する場所(GitHub など)、PR = 本流への取り込みの依頼。
- 必要な理由は、過去に戻れる、履歴が分かる、複数人で同時に作業できる、安全に試せる、バックアップになる。
- 使わないと、ファイルが増える、戻せない、上書きの事故、履歴が追えない、共有で取り違える、といった問題が起きる。
- このリポジトリでは、1問1コミット、ブランチで作業、PR にまとめて取り込む流れで使っている。
