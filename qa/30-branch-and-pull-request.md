# Q30. ブランチとPull Request

## 問題

- ブランチとは何ですか？
- Pull Request の目的は何ですか？
- なぜ全員が main に直接変更しないのですか？

## 回答

ブランチは、本流(多くの場合 `main`)から枝分かれした作業用の流れです。`main` はそのままにして、別のブランチの中で変更を進められます。ブランチの中で何を変えても `main` には影響せず、うまくいかなければブランチごと捨てられます。

Pull Request(PR)の目的は、ブランチで行った変更を `main` に取り込んでよいか、確認を求めることです。取り込む前に、次のことができます。

- 変更の中身を、他の人が見て確認する(レビュー)。見落としや間違いを、取り込む前に見つけられます。
- 自動テストなどのチェックを走らせる。
- 何をなぜ変えたかの説明を残す。あとから経緯を追えます。

確認が済んでから、`main` に取り込みます(マージ)。

全員が `main` に直接変更しないのは、次の理由からです。

- `main` を、いつも動く正しい状態に保つため: `main` は本番に出す元になることが多い基準の流れで、未完成や不具合のある変更が直接入ると、全員が影響を受けます。
- 確認を通してから入れるため: 直接変更すると、レビューやテストを通らないまま変更が入ってしまいます。
- 同時作業でぶつからないため: 全員が同じ場所を直接触ると、お互いの変更を上書きしたりぶつかったりします。ブランチで分ければ、それぞれ独立して進められます。
- 戻しやすくするため: 問題が出たとき、どの PR で入った変更かが分かるので、その変更だけを取り消せます。
- 経緯を残すため: PR に目的と議論が残ります。

このリポジトリでも、`main` には直接変更せず、ブランチ `docs/1-add-qa-answers` で作業しています。最後に全問を1つの PR にまとめ、本文に `Closes #1` を入れて、取り込むと Issue #1 が閉じるようにします。取り込み(マージ)は、人が確認して行います。

ブランチは本流に影響しない作業用の流れ、PR は取り込んでよいかの確認を求める依頼であり、`main` に直接変更しないのは、確認を通っていない変更で基準の流れを壊さないためだと理解しました。

## 理解のメモ

- ブランチ = 本流(`main`)から枝分かれした作業用の流れ。中で何を変えても `main` に影響せず、捨てることもできる。
- PR の目的 = ブランチの変更を `main` に取り込んでよいか、確認を求めること。レビュー、自動テスト、説明の記録ができる。確認後にマージして取り込む。
- `main` に直接変更しない理由は、`main` を正しい状態に保つ、確認を通す、同時作業でぶつからない、戻しやすくする、経緯を残す。
- このリポジトリでは、ブランチ `docs/1-add-qa-answers` で作業し、全問を1つの PR にまとめ、`Closes #1` を入れる。マージは人が行う。
