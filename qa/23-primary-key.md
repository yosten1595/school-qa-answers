# Q23. 主キー（PRIMARY KEY）

## 問題

tasksテーブルの `id` は主キーです。

- 主キーとは何ですか？
- なぜ必要ですか？

## 回答

主キー(PRIMARY KEY)は、テーブルの中で1行を確実に特定するための列です。主キーの列は、値が重複せず、空にもなりません。`tasks` テーブルでは `id` 列がこれにあたり、`id` の値が決まれば、タスクが1件に決まります。`id` の値は、タスクを作成したときに、データベースやバックエンドが自動で付けるのが一般的です。

主キーが必要なのは、次の理由からです。

- 1行を確実に指すため: 同じタイトルのタスクが複数あっても、`id` が違えば区別できます。タイトルや内容は同じ値が入ることがあるため、1行の特定には使えません。
- 正しい行だけを操作するため: 更新や削除のとき、「`id` が 2 の行」と指定すれば、狙った1行だけを変えられます。間違って別の行を変えたり消したりする心配がありません。
- API の宛先に使うため: `/api/tasks/2` の `2` は、この `id` の値です。フロントエンドとバックエンドが、同じ1件を指してやり取りできます。
- 表同士をつなぐため: 別のテーブル(たとえば、コメントの表)が、「どのタスクについてのものか」を、タスクの `id` で参照できます。

ほかに、主キーには探索を速くする仕組みが自動で付くため、`id` で行を探すのが速くなるという利点もあります。

主キーは、重複せず空にならない値で1行を確実に特定する列であり、同じ内容の行があっても区別でき、正しい1行だけを操作できるようにするために必要だと理解しました。

## 理解のメモ

- 主キー = テーブルの中で1行を確実に特定する列。値は重複せず、空にならない。`tasks` テーブルでは `id`。
- `id` の値は、作成時に自動で付けるのが一般的。
- 必要な理由は、1行を確実に指す、正しい行だけを操作する、API の宛先に使う(`/api/tasks/{id}`)、表同士をつなぐ。
- タイトルのような、同じ値が入りうる列は、1行の特定には使えない。
