# Q28. SQLとORM

## 問題

- SQLとはどのようなものですか？
- ORMの役割とは何ですか？

## 回答

SQL は Structured Query Language の略で、リレーショナルデータベース(表の形でデータを持つデータベース)に、何をしてほしいかを伝えるための専用の言葉です。バックエンドがデータベースにつなぐとき、SQL で依頼します。CRUD に対応する基本の命令があり、`tasks` テーブルの例(列名は仮)では次のようになります。

- Create: `INSERT INTO tasks (title) VALUES ('牛乳を買う');` で、行を追加します。
- Read: `SELECT * FROM tasks WHERE id = 2;` で、`id` が 2 の行を取り出します。
- Update: `UPDATE tasks SET list_name = '完了' WHERE id = 2;` で、`id` が 2 の行の値を書き換えます。
- Delete: `DELETE FROM tasks WHERE id = 2;` で、`id` が 2 の行を消します。

ORM は Object-Relational Mapping の略で、データベースの表や行を、プログラムの中のオブジェクトに対応づけ、プログラムの書き方のままデータベースを操作できるようにする仕組みです。ORM を使うと、SQL を直接書かなくても、プログラムの普通の書き方でデータベースを操作でき、裏で ORM が SQL を作ってデータベースに送ります。

ORM の役割は、次のとおりです。

- 翻訳: プログラムの言葉とデータベースの言葉(SQL)の間を橋渡しします。
- 書く量を減らす: 毎回 SQL の文を書かなくて済みます。
- 間違いを減らす: 列の名前や型をプログラムの側で扱えるので、書き間違いに気づきやすくなります。入力値を安全な形で SQL に渡す仕組みも備わっていて、SQL インジェクションのような危険な入力による攻撃を防ぎやすくなります。
- データベースの違いを吸収する: データベースの製品を変えても、プログラムをあまり変えずに済むことがあります。

ただし、裏でどんな SQL が作られているかが見えにくく、思わぬ遅い処理になることがあります。また、複雑な検索は ORM では書きにくく、SQL を直接書くこともあります。

SQL はデータベースに依頼するための言葉であり、ORM はプログラムの書き方のままデータベースを操作できるようにする橋渡し役だと理解しました。

## 理解のメモ

- SQL = Structured Query Language。リレーショナルデータベースに依頼するための専用の言葉。
- 基本の命令は、CRUD に対応する。INSERT = 追加、SELECT = 取り出し、UPDATE = 書き換え、DELETE = 削除。
- ORM = Object-Relational Mapping。表や行をプログラムのオブジェクトに対応づけ、SQL を直接書かずにデータベースを操作できるようにする。裏で SQL を作って送る。
- ORM の役割は、翻訳、書く量を減らす、間違いを減らす(SQL インジェクションも防ぎやすい)、データベースの違いを吸収する。
- 注意点は、裏の SQL が見えにくいこと、複雑な検索は SQL を直接書くこともあること。
- このアプリが ORM を使っているかは、確認していない。
