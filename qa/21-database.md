# Q21. データベースとは

## 問題

データベースとは何ですか？

ExcelやCSVで保存する方法と比べて何が優れていますか？

## 回答

データベースは、データを整理された形で保存し、必要なときに素早く取り出したり、書き換えたりできる仕組みです。多くの場合、データを表の形で持ち、表の1行が1件のデータ、列が項目にあたります。データベースを管理するソフトに、バックエンドが「このカードを保存して」「このカードを取り出して」と頼むことで、アプリがデータを扱います。

Excel や CSV は1つのファイルにデータを書いたもので、個人の集計や少人数の簡単な管理には便利です。ただし、アプリのデータの置き場としては、データベースのほうが優れています。

- 同時利用: Excel や CSV は、複数の人が同時に書き換えると、お互いを上書きしたり衝突したりします。データベースは、同時に使っても整合性を保つ仕組みを持っています。
- データ量: Excel や CSV は、件数が増えると遅くなります。データベースは、索引(インデックス)などによって、大量のデータでも素早く探せます。
- 入力のルール: Excel や CSV は、日付の欄に文字を入れても通ってしまいます。データベースは、型や必須などのルールを強制できます。
- 途中で失敗したとき: Excel や CSV は、処理の途中で失敗すると、中途半端な状態で残ることがあります。データベースは、「全部成功するか、全部なかったことにする」仕組み(トランザクション)を持っています。

このアプリ(トレロ風アプリ)では、多くの利用者が同時にカードを追加したり動かしたりします。データベースなら、同時の操作でもデータが壊れず、カードを動かす途中で失敗しても、動かす前の状態に戻せます。

Excel や CSV が劣っているわけではなく、使う目的が違います。多くの人が同時に使い、データが増え続け、正しさを保つ必要があるアプリでは、データベースが向いていると理解しました。

## 理解のメモ

- データベース = データを整理して保存し、素早く取り出したり書き換えたりできる仕組み。データは表の形(行 = 1件、列 = 項目)で持つことが多い。
- Excel / CSV と比べた強みは、同時利用、大量データの検索、入力ルールの強制、途中で失敗したときの安全(トランザクション)。ほかに、表同士の関連の維持やアクセス権の管理もできる。
- Excel / CSV は劣っているのではなく、個人の集計や少人数の簡単な管理に向く。目的が違う。
- バックエンドが、データベースにデータの保存や取り出しを頼む。
