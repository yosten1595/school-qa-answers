# Q17. 同期処理と非同期処理

## 問題

「同期処理」と「非同期処理」の違いを、日常生活の例えで説明してください。

なぜWeb通信では非同期処理が必要ですか？

## 回答

「同期処理」は、1つの処理が終わるまで待ってから、次の処理に進む方法です。待っている間は、ほかのことができません。「非同期処理」は、処理を頼んだら終わるのを待たずに次のことを進め、頼んだ処理が終わったら、その結果を受け取って続きをする方法です。

日常生活の例えでは、レストランの店員にあたります。同期の場合、店員は、客Aの注文を厨房に伝えたあと、料理ができるまでその場に立って待ち、その間、ほかの客の注文を受けられません。非同期の場合、店員は、客Aの注文を厨房に伝えたらすぐに客Bの注文を取りに行き、料理ができたら呼ばれて、客Aの席に運びます。

Web 通信で非同期処理が必要なのは、リクエストを送ってからレスポンスが返るまでに時間がかかることがあるからです。同期処理だと、その間、ページの表示や操作が止まります。ただし、止まるのはブラウザのタブの中のページで、ブラウザや OS の操作は止まりません。非同期処理なら、リクエストを送ったあともページは動き続け、レスポンスが返ってきた時点で、その結果を受け取って画面に反映できます。

新しいカードを追加する程度の処理は一瞬で終わるため、違いは気づきにくいです。しかし、通信が遅いとき、処理が重いとき、サーバーが混んでいるときには、待ち時間が長くなり、差が出ます。そのため、Web 通信では、最初から非同期にしておきます。

同期は終わるまで待つ方法、非同期は待たずに進めて終わったら結果を受け取る方法であり、時間のかかる Web 通信では、ページが止まらないように非同期を使うと理解しました。

## 理解のメモ

- 同期 = 終わるまで待ってから次へ進む。非同期 = 待たずに次へ進み、終わったら結果を受け取る。
- 例え: 料理ができるまで立って待つ店員が同期、ほかの客の注文を取りに行って、できたら運ぶ店員が非同期。
- Web 通信は、レスポンスが返るまでに時間がかかることがある。同期だと、そのタブのページの表示や操作が止まる。ブラウザや OS の操作は止まらない。
- 速い処理(カードの追加など)では違いを実感しにくいが、通信が遅い、処理が重い、サーバーが混んでいるときに差が出る。
- 回答に例えを入れたのは、問題が日常生活の例えを求めているため(この問題だけの扱い)。
