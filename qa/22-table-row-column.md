# Q22. テーブル・行・列

## 問題

以下をExcelのシートに例えて説明してください。

- テーブル
- 行（レコード）
- 列（カラム）

tasksテーブルで具体例も挙げてください。

## 回答

Excel のシートに例えると、次のように対応します。

- テーブル: 1枚のシートにあたります。同じ種類のデータをまとめた表で、タスクの表、ユーザーの表のように、何についての表かで分けます。
- 行(レコード): シートの横1本の並びにあたります。1件分のデータをひとまとまりで表します。
- 列(カラム): シートの縦1本の並びにあたります。全部の行に共通する項目を表します。

Excel との大きな違いは、データベースでは、各列に入れるデータの種類(数字、文字、日付など)やルールを厳密に決められることです。

`tasks` テーブルの具体例を挙げます。列構成は、ここでは例として仮に置いたものです。

| id | title | list_name | created_at |
|---|---|---|---|
| 1 | 牛乳を買う | やること | 2026-10-20 |
| 2 | 資料を作る | 進行中 | 2026-10-21 |
| 3 | 部屋を掃除する | 完了 | 2026-10-22 |

- テーブル: この表全体が `tasks` テーブルです。
- 行(レコード): たとえば、2行目の「2 / 資料を作る / 進行中 / 2026-10-21」は、タスク1件分です。
- 列(カラム): たとえば、`title` 列は、全タスクのタイトルが縦に並ぶ項目です。`id` 列は、1件ごとの固有の番号の項目で、`/api/tasks/2` の `2` は、この `id` 列の値にあたります。

アプリの操作は、表への操作に対応します。タスクを作成すると行が1つ追加され、取得すると条件に合う行が取り出され、一部を修正すると行の一部の列の値が書き換わり、削除すると行が1つ消えます。

テーブルは1枚のシート、行は1件分のデータ、列は項目にあたり、`tasks` テーブルでは、1行が1つのタスクで、各列がタスクの項目を表していると理解しました。

## 理解のメモ

- テーブル = Excel の1枚のシート。行(レコード) = 横1本 = 1件分のデータ。列(カラム) = 縦1本 = 項目。
- 列には決まった種類のデータしか入れられず、Excel よりルールを厳密に決められる。
- `tasks` テーブルの例では、1行が1つのタスク。`id` 列は、1件ごとの固有の番号で、`/api/tasks/{id}` の `{id}` にあたる。
- 作成 = 行の追加、取得 = 行の取り出し、一部修正 = 一部の列の値の書き換え、削除 = 行の削除。
- 列構成は仮の例であり、実際のアプリの列とは異なる可能性がある。
- 回答に Excel の例えを入れたのは、問題がその例えを求めているため(この問題だけの扱い)。
